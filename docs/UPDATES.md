# Автообновление программы

Мастерам больше не нужно рассылать архивы: программа сама предлагает обновиться.

## Как это работает у мастера (Windows)

1. После входа программа читает последнюю версию из `app_releases` (platform = windows).
2. Если `build_number` там больше, чем у программы, появляется окно «Новая версия X» с описанием и размером.
   «Позже» — окно закрывается до следующего запуска (вверху остаётся полоска «Доступна версия X»).
   Для обязательной версии (`is_mandatory`) работа без обновления невозможна.
3. «Обновить»: zip скачивается в фоне с прогрессом по временной ссылке из приватного bucket `releases`,
   сверяется SHA-256, распаковывается, программа закрывается, файлы заменяются (adb и scrcpy из папки
   программы останавливаются перед заменой), программа открывается заново уже новой версией.

Android: ссылка открывается в браузере, APK ставится системным установщиком. PWA обновляется сама.

## Как выпустить новую версию (администратор)

1. В `pubspec.yaml` увеличить версию и номер сборки: `version: 2.0.1+3` (номер после `+` всегда растёт).
2. Собрать: `flutter build windows --release --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...`
3. В `build\windows\x64\runner\Release` должны лежать папки `adb\` и `scrcpy\` (они не пересобираются, остаются).
4. Упаковать содержимое папки Release (не саму папку) в zip.
5. Опубликовать (ключ service_role только в переменных окружения):
   `dart run tool/publish_release.dart --file nox.zip --platform windows --notes "Что нового"`
   Добавить `--mandatory`, если старые версии должны обязательно обновиться. `--dry-run` — только проверка.

Отменить выпуск: в таблице `app_releases` поставить `is_active = false` у этой строки.
