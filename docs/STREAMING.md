# Трансляция для администратора: экран ноутбука мастера, экран ГУ, камера

Требование: администратор в реальном времени смотрит
1. экран ноутбука мастера (Windows-приложение),
2. экран головного устройства (ГУ) автомобиля,
3. камеру (телефон мастера или веб-камера ноутбука),

и смотреть может с телефона (PWA/APK), с ноутбука (браузер или Windows-приложение) и с ГУ автомобиля (Android, браузер или APK).

## Выбор технологии

Видео в реальном времени между произвольными сетями (мобильный интернет мастера, Wi-Fi админа) = **WebRTC**.
Прямое P2P-соединение без сервера ломается за NAT операторов и плохо работает при нескольких зрителях, поэтому
используется медиасервер (SFU) **LiveKit**:

- открытый (Apache 2.0), есть облако LiveKit Cloud с бесплатным лимитом и возможность поставить на свой сервер;
- встроенные TURN/STUN (работает через NAT мобильных операторов);
- официальный Flutter SDK `livekit_client`: Windows (включая захват экрана), Android, iOS, Web —
  одна кодовая база для всех клиентов, в том числе для просмотра в PWA;
- Ingress (RTMP/WHIP) — приём готового H.264-потока, нужен для экрана ГУ;
- Egress — запись трансляций в файл (по желанию, позже).

Supabase остаётся единственным бэкендом для данных и прав; LiveKit только передаёт видео.
WebSockets отдельно не нужны: сигналинг LiveKit идёт по своему WebSocket, а команды «начать/остановить
трансляцию» и список мастеров онлайн — через Supabase Realtime.

```
 Ноутбук мастера (Windows-приложение)                 LiveKit (SFU + TURN)           Зрители (админ)
 ┌───────────────────────────────────┐                ┌───────────────┐      ┌─────────────────────┐
 │ захват экрана ноутбука ───────────┼─ WebRTC ──────▶│               │─────▶│ телефон: PWA / APK  │
 │ веб-камера (опц.) ────────────────┼─ WebRTC ──────▶│ комната       │─────▶│ ноутбук: браузер /  │
 │ adb ─▶ scrcpy-server на ГУ ─▶ H.264┼─ RTMP/WHIP ──▶│ master-<id>   │      │   Windows-прил.     │
 └───────────────────────────────────┘    (Ingress)   │               │─────▶│ ГУ: браузер / APK   │
 Телефон мастера (PWA/APK): камера ────── WebRTC ────▶│               │      └─────────────────────┘
                                                      └───────────────┘
        ▲ токены доступа                                     ▲
        └──────── Supabase Edge Function `stream-token` ─────┘   (проверяет роль: мастер / админ)
 Supabase Realtime: присутствие мастеров онлайн, команды start/stop, статус трансляции
```

## Источники

| Источник | Где захватывается | Как |
|---|---|---|
| Экран ноутбука | Windows-приложение мастера | `livekit_client` screen share (захват экрана Windows) |
| Экран ГУ | Windows-приложение мастера по ADB | `scrcpy-server` (Apache 2.0) запускается на ГУ через adb и отдаёт непрерывный H.264; приложение передаёт поток в LiveKit Ingress (встроенный `ffmpeg.exe` рядом с `adb\`, без перекодирования). Запасной вариант для старых ГУ: `screencap` 2–4 кадра/с |
| Камера | телефон мастера (PWA или APK) или веб-камера ноутбука | `livekit_client` camera track. В PWA на iPhone камера работает (Safari поддерживает отправку видео) |

Каждый источник — отдельная дорожка в комнате мастера: `screen-laptop`, `screen-hu`, `camera`.
Админ видит сетку из трёх окон и может развернуть любое.

## Права и прозрачность

- Трансляцию запускает админ из панели (строка в `stream_sessions`), приложение мастера получает команду
  через Supabase Realtime и начинает публиковать.
- **Мастер всегда видит, что идёт трансляция**: красная плашка «Идёт трансляция администратору» поверх окна
  и в трее, перечень источников. Факт трансляции пишется в журнал (кто, когда, какие источники).
  Условие о трансляции включается в соглашение с мастером при первом входе (галочка согласия, хранится в `masters`).
- Экран ГУ может показывать личные данные владельца авто (контакты, маршруты) — трансляция только во время
  выполнения услуги или по явному запросу админа, с журналом.
- Токены LiveKit выдаёт только Edge Function: мастер — право публиковать в свою комнату `master-<uuid>`,
  админ — право смотреть любую комнату. Ключи LiveKit (API key/secret) хранятся только в секретах Supabase,
  не в приложениях и не в git.

## Изменения в базе (миграция 0005_streaming.sql)

- `masters.stream_consent_at timestamptz` — когда мастер согласился.
- `stream_sessions (id, master_id, requested_by, sources text[], status 'requested'|'live'|'ended', started_at, ended_at)`,
  RLS: админ — всё, мастер — свои строки.
- Realtime-канал `presence:masters` — кто из мастеров сейчас в приложении, подключено ли ГУ.

## Клиенты (одна кодовая база Flutter)

| Клиент | Роль | Сборка |
|---|---|---|
| Windows-приложение | мастер: услуги + публикация экрана ПК/ГУ/веб-камеры; админ: панель | `flutter build windows` |
| PWA | мастер: кабинет + камера; админ: панель и просмотр | `flutter build web` (HTTPS-хостинг) |
| Android APK | мастер: кабинет + камера (+ услуги по OTG позже); админ: панель и просмотр; ставится и на ГУ | `flutter build apk` |

Админ-панель — отдельный раздел приложения, открывается только если пользователь есть в `admins`:
мастера онлайн, трансляции, пополнение баланса, заявки на активацию и возвраты.

## Этапы

1. **Основа под все платформы**: условные импорты `dart:io` (web-сборка), адаптивная вёрстка, раздел «Админ»
   с ролями, сборки web и apk. Миграция 0005.
2. **Трансляция экрана ноутбука и камеры**: Edge Function `stream-token`, LiveKit, публикация из Windows и PWA/APK,
   просмотр в админ-панели на любом устройстве, плашка у мастера.
3. **Экран ГУ**: scrcpy-server + ffmpeg → LiveKit Ingress, проверка на реальном ГУ Changan.
4. Хостинг PWA, раздача APK по ссылке, автообновление APK.

Что нужно от владельца: аккаунт LiveKit Cloud (бесплатный) — ключи вносятся им самим в секреты Supabase;
HTTPS-хостинг для PWA (Cloudflare Pages бесплатно или свой домен).
