# Мобильная версия: PWA + APK без магазинов

Цель: мастер работает с телефона без Play Market и App Store.
Одна кодовая база Flutter (этот репозиторий), две сборки:

| Сборка | Где работает | Что умеет | Как ставится |
|---|---|---|---|
| **PWA** (`flutter build web`) | iOS Safari, Android Chrome, любой браузер | Кабинет: вход, баланс, VIN и заявки на активацию, история, заявки на возврат | Открыть ссылку → «На экран Домой» |
| **APK** (`flutter build apk`) | Android 8+ | Всё из PWA + выполнение услуг на ГУ по кабелю USB-OTG | Скачать .apk по ссылке → установить (разрешить «из этого источника») |
| Windows (уже есть) | ПК | Всё | zip / Auto-Up |

## Главное ограничение: ADB с телефона

Услуги выполняются через ADB по USB. Возможности по платформам:

- **iOS** — нет доступа к USB-устройствам ни из браузера, ни из приложения без MFi. Выполнять услуги с iPhone нельзя, только кабинет.
- **Android APK** — USB Host API (кабель OTG телефон → ГУ). ADB-протокол реализуется в приложении
  (протокол ADB открытый: пакеты CNXN/AUTH/OPEN/WRTE поверх USB bulk-передачи, Kotlin-код через platform channel;
  готовую библиотеку выбрать на этапе 3 после проверки поддержки USB). adb.exe не нужен.
- **Android Chrome PWA** — технически возможно через WebUSB (библиотека `@yume-chan/adb`), но нестабильно:
  нужен HTTPS, разрешение на каждое подключение, вкладка должна быть активной всю установку (1,6 ГБ голосового пакета).
  Поэтому выполнение услуг из PWA не делаем; PWA = кабинет.

Итог: **PWA — кабинет для всех телефонов; APK — полный режим для Android.**

## Как ложится на текущий код

Уже готово к этому:
- `lib/adb/adb_executor.dart` — интерфейс `AdbExecutor` (shell, pipe, readDeviceInfo, reboot).
  Добавляется реализация `UsbAdbExecutor` (Android), Windows-реализация `ProcessAdbExecutor` остаётся.
- Сервер (Supabase RPC `start_job`, `finish_job`, баланс, сценарии) не меняется: телефон — такой же клиент.
- Расшифровка пакетов потоком в памяти (`lib/security/payload_cipher.dart`) работает на Android без изменений.

Что нужно доработать:
1. **Разделить платформенный код.** `dart:io` сейчас импортируют `adb_executor.dart`, `adb_client.dart`,
   `job_backend.dart`, `job_controller.dart`, `apk_picker.dart`. Для web-сборки — условные импорты
   (`if (dart.library.io)`) и провайдер `adbAvailableProvider`: в PWA блок «Подключение к автомобилю» скрыт.
2. **Мобильная вёрстка.** Главный экран сейчас под широкое окно ПК: адаптивный layout (узкий экран — вкладки
   «Кабинет / Автомобиль / История»).
3. **Android USB.** `android/` + `UsbAdbExecutor`: запрос разрешения на USB-устройство, ключ ADB (RSA)
   хранится в приложении, на ГУ один раз подтверждается «Разрешить отладку». Свои APK мастера — выбор файла
   из памяти телефона (`file_picker` уже есть).
4. **Обновления.**
   - PWA: service worker Flutter обновляет сам при новой публикации.
   - APK: таблица `app_releases` уже есть, добавляется `platform = 'android'`. Приложение сравнивает
     `build_number`, скачивает APK из bucket `releases` и открывает установщик
     (разрешение `REQUEST_INSTALL_PACKAGES`). Подпись APK — один постоянный ключ (keystore хранится только у
     администратора, не в git), иначе обновление поверх не установится.
5. **Хостинг PWA.** Статические файлы `build/web`: Cloudflare Pages / Netlify / Supabase Storage + свой домен.
   Нужен HTTPS (без него PWA не ставится на экран).

## Безопасность

- В PWA и APK, как и в Windows, только публичный ключ (anon/publishable); service_role — никогда.
- `prep.sh` (доступ ADB) по-прежнему лежит только в зашифрованных пакетах на сервере.
- APK распространяется по ссылке: ссылка на bucket `releases` выдаётся только вошедшим мастерам (signed URL).

## Порядок работ

1. Условные импорты + web-сборка кабинета (PWA), адаптивная вёрстка. — можно тестировать на iPhone и Android.
2. Android-проект, сборка APK кабинета, Auto-Up для APK.
3. `UsbAdbExecutor` + проверка на реальном ГУ Changan через OTG (нужен телефон с OTG и кабель).
