# Проверка защиты nox.drive от взлома, 20.10.2026

Проверялось на боевом сервере (только чтение, вызовы с несуществующими идентификаторами без последствий),
по миграциям в репозитории и по собранному выпуску 2.0.30. Под мастером в бою не входили.

## Критично

### 1. Вход через Telegram можно перехватить (на сервере старая версия функции)
- На сервере работает старая `telegram-auth` без кода подтверждения: все входы с 13.10 по 19.10 прошли без кода
  (`telegram_logins.code_hash` пустой).
- Атака: злоумышленник запрашивает вход, получает ссылку на бота и уговаривает мастера или админа нажать её
  («подтверди вход»). После нажатия программа злоумышленника получает сессию жертвы.
- Исправление уже есть в репозитории: `supabase/functions/telegram-auth/index.ts` (6-значный код из бота, 5 попыток).
  Программа мастера умеет вводить код с 2.0.15, у всех мастеров обязательная 2.0.29+.
- Нужно: опубликовать функцию и выключить старый режим:
  ```
  supabase functions deploy telegram-auth --project-ref qpfuosdqjcfbcubsmvrb
  supabase secrets set TELEGRAM_LEGACY_LOGIN=off --project-ref qpfuosdqjcfbcubsmvrb
  ```
  Для этого нужен токен доступа аккаунта-владельца проекта (Wardecs0312) или вход в панель Supabase.

## Важно (решение за владельцем, это правила оплаты или входа)

### 2. Бесплатный повтор можно получить подделанной программой
- `service_charge`: повтор бесплатный, если уже была успешная услуга на тот же VIN и тот же серийник ГУ.
  VIN и серийник присылает программа, сервер их проверить не может, и мастер в условии не учитывается.
- Подделанная программа может выдавать каждую новую машину за уже обслуженную (в том числе чужую) и не платить.
- Предложение: бесплатный повтор только тому же мастеру (`a.master_id = auth.uid()`) и не чаще N раз за период
  (например 3 за 30 дней на VIN), остальное платно.

### 3. Почта админа видна любому
- `admin_login_email(p_username)` открыта анониму и по @нику админа возвращает его почту (нужна для входа на сайт
  админки по @нику). Злоумышленник узнаёт почту и может подбирать пароль.
- Предложение: вход на сайт админки по почте, а функцию закрыть для анонима; либо перенести вход по @нику
  в серверную функцию, которая сама проверяет пароль и не раскрывает почту.

## Ограничения, которые не закрыть полностью
- Мастер, который заплатил, получает ключ расшифровки на время задания и теоретически может сохранить APK.
  Файлы ставятся на чужие ГУ как обычные APK, поэтому полностью это не предотвратить.
- Любой активный мастер может скачать зашифрованные файлы прошивок (фоновая загрузка, `can_read_payload`).
  Без ключа они бесполезны, ключи выдаёт только `start_job` после оплаты.
- Упавшее задание не засчитывается в пакет: мастер может заплатить дважды (см. память проекта, 20.10).

## Проверено и в порядке
- Без входа (ключ из программы) сервер отдаёт только список выпусков программы; все таблицы и хранилища закрыты,
  все функции с повышенными правами отвечают `permission denied`.
- Таблицы с ключами (`payloads`, `scenarios`) мастеру не видны; ключи выдаёт только `start_job`.
- Мастер видит только свои строки (баланс, журнал, задания), менять баланс, роль и цены не может.
- Неодобренный мастер (`pending`) услуги запускать не может (`start_job` → `MASTER_BLOCKED`).
- Админские функции проверяют `nox_is_admin()` на сервере.
- Трансляции: мастер только отправляет картинку в свою комнату, смотреть может только админ.
- Выпуск 2.0.30: внутри нет ключа service_role и ключа подписи; есть только публичный ключ и заводской пароль ADB ГУ.
- Обновления подписаны Ed25519, программа проверяет подпись.
- Новая таблица диагностики (`20261021_02`): мастер только добавляет свою запись, читает и удаляет только админ.

### Файлы прошивок
- На диске мастера лежат только зашифрованные файлы (кэш), ключи расшифровки держатся в памяти на время задания
  и не сохраняются.
- Полностью защитить файлы нельзя: после установки APK лежат на ГУ клиента в открытом виде и скачиваются через
  ADB (пароль общеизвестен). Мастер, оплативший услугу, теоретически может перехватить ключ задания.
- Поднимаем планку: с этого коммита сборка выпуска запутывает код (`--obfuscate --split-debug-info`),
  символы для расшифровки ошибок остаются в `build\symbols\<версия>` у администратора. Действует со следующего выпуска.
- Можно дальше (по решению): привязка TLS к сертификату сервера (затрудняет перехват ключа программами-прослушками),
  одноразовые ключи на задание вместо постоянных ключей файлов.
